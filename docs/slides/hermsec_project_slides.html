A CVE aware AI security review agent for developers shipping code fast.

Agentic tool calls Static analysis CVE enrichment Daily reports

The problem

Production teams move quickly

  • Developers push code many times in a day.
  • Manual security scans are often skipped.
  • Raw scanner output is difficult to read.
  • Dependency CVEs may be noticed too late.

Project question

Can an agent automatically review the code shipped during the day and return a clear security and quality report to programmers?

What we are building

Manual mode

  • User enters a GitHub URL or local repository path.
  • The agent runs security tools on demand.
  • A terminal and Markdown report are generated.

Automated mode

  • Hermes agent harness runs scans on a schedule.
  • The scan focuses on code shipped that day.
  • A daily report is delivered to the team.

Agent workflow

Repository GitHub URL or local path
->
hermSec Agent Coordinates scanners, memory, model calls, and report writing
->
Daily Report Issue, file, severity, CVE or CWE, explanation, suggested fix 
> hermsec scan https://github.com/team/service-api
running bandit, semgrep, pip-audit, osv-scanner
report generated 3 new issues, 2 fixed issues, 1 critical CVE

Tools and technologies

Agent layer

  • Hermes agent harness
  • OpenRouter Agent TUI
  • Agentic tool calls
  • Memory for scan history

Security tools

  • Bandit for Python security
  • Semgrep for custom rules
  • pip-audit and OSV-Scanner
  • Gitleaks for secrets

Model and delivery

  • BYOM through OpenRouter
  • Ollama or LM Studio
  • Telegram MCP notifications
  • Markdown, JSON, and PDF reports

Why compare tools?

Confidence scoring

  • High confidence when Bandit and Semgrep agree.
  • Medium confidence when one scanner reports evidence.
  • Low confidence for AI-only quality concerns.
  • Confirmed CVE only when dependency data proves it.
Finding: possible command injection

Bandit:  subprocess with shell=True
Semgrep: dangerous subprocess use
CWE:     CWE-78
Status:  high confidence

Fix: avoid shell=True and pass arguments as a list.

Report returned to programmers

Issue Location Severity Evidence Suggested fix
SQL injection pattern app/routes.py High CWE-89, Semgrep rule Use parameterized queries.
Vulnerable dependency requirements.txt Critical Confirmed CVE match Upgrade package to patched version.
Hardcoded secret settings.py High Gitleaks finding Move secret to environment variables.

Evaluation plan

Detection test

Use a demo repository with known SQL injection, command injection, hardcoded secrets, and outdated dependencies.

Comparison test

Compare hermSec output with raw Bandit, Semgrep, pip-audit, OSV-Scanner, and Gitleaks results.

Report quality test

Check whether each finding has a clear explanation, evidence, severity, and useful fix recommendation.

Final project direction

hermSec turns scattered scanner results into a daily developer security review. It uses static analysis tools for evidence, CVE sources for confirmed dependency risk, memory for trend tracking, and a bring your own model approach for clear explanations.
