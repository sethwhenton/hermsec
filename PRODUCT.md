# Product

## Register

product

## Users

Hermsec is for developers and small teams who are building quickly and need a security-focused workspace beside their code. They use it while reviewing a local repository, running scanner-backed checks, reading evidence, asking a model to explain findings, and deciding what to fix next.

## Product Purpose

Hermsec is a local-first desktop security assistant for repositories. It inspects projects, runs defensive scanners and agent inspections, preserves raw evidence, generates local reports, and helps users understand and prioritize security fixes without becoming an unrestricted coding agent.

Success means a user can select a project, understand its security posture, run the right scan mode, watch progress, inspect findings, open the dashboard/report artifacts, configure providers and automations, and leave with a clear fix plan.

## Brand Personality

Calm, precise, trustworthy.

Hermsec should feel like a serious security workstation with the approachable rhythm of a modern chat IDE. It should be focused and low-noise, but not cold. The assistant voice should be conversational around security work while staying evidence-led and bounded.

## Anti-references

Hermsec should not look like a generic SaaS dashboard, a marketing landing page, a toy hacker terminal, or a heavy enterprise admin panel. Avoid flashy cyberpunk visuals, gratuitous gradients, confusing custom controls, oversized empty chrome, and decorative effects that make the security workflow harder to scan.

## Design Principles

1. Evidence first: scanner and agent output should be traceable, readable, and never hidden behind decoration.
2. Earned familiarity: use predictable app-shell, chat, settings, and dashboard patterns so users can trust the tool quickly.
3. Progressive depth: show the next useful action first, then let users expand progress, reports, settings, and technical detail when they need it.
4. Quiet confidence: visual polish should come from alignment, spacing, motion restraint, and consistent controls rather than spectacle.
5. Local control: paths, reports, providers, and automation state should always feel understandable and owned by the user.

## Accessibility & Inclusion

Target WCAG AA contrast for text and controls. Keep keyboard focus visible, support reduced motion, avoid relying on color alone for scanner state, preserve readable line lengths in chat/report explanations, and keep touch/click targets comfortable in compact desktop windows.
