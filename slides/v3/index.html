HermSec

Security review for local code projects.

A desktop assistant that scans repositories, explains evidence, and creates clean reports for developers.

01 Why we built it

Security tools should be easier to run.

Many developers do not scan often because setup is slow, reports are noisy, and each language needs different tools.

HermSec turns that work into one simple desktop flow.

One workflow Pick a project, choose the scan mode, and let HermSec handle the scanning steps.
Clear evidence Findings keep file paths, lines, scanner rules, severity, confidence, and remediation guidance.
Useful reports The final output is readable in chat, dashboard pages, JSON, Markdown, HTML, and PDF.

HermSec Features

03 How the harness moves

Deep assisted scan is scanner-backed review plus model explanation.

HermSec checks what the project is, prepares the right tools, runs scanners, normalizes evidence, and then asks the model to explain the confirmed findings.

InspectFind languages, frameworks, manifests, lockfiles, and config files.
Choose toolsPick Semgrep, Gitleaks, OSV, Trivy, Bandit, Checkov, and others only when useful.
Run scansExecute managed scanners safely, with timeouts and progress events.
NormalizeTurn every result into one HermSec finding format with evidence and fingerprints.
ReportWrite JSON, HTML, Markdown, dashboard artifacts, and PDF output.

04 Review modes

We compared four ways to review code.

Each mode uses the same report format, but the evidence is collected and judged differently.

Deep assistedScanners run first. The model summarizes and explains scanner-backed evidence.
Single AgentOne model inspects focused code candidates with bounded read and search tools.
MoASpecialist agents inspect candidates. A judge and aggregator merge accepted evidence.
Scanner + MoAScanners and agents run independently. A judge validates and merges both evidence sources.
Scanner-backedinspect -> choose scanners -> run scanners -> model explanation -> report
Agent-onlycandidate discovery -> focused task bundle -> one agent -> local evidence check
Multi-agentcandidate discovery -> specialist agents -> false-positive judge -> aggregator
Hybridscanner findings + independent MoA candidates -> judge -> final revalidation

07 What we learned

The best result came from combining tools and agents.

Scanners gave grounded evidenceThey were useful for secrets, dependency risks, known patterns, and repeatable results.
Agents helped with contextFocused investigation tasks helped the model inspect code paths instead of guessing from a broad prompt.
Judging matteredThe final judge and revalidation pass helped merge duplicates and reject unsupported claims.
